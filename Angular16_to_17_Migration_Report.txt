SECTION 4 : NEW CONTROL FLOW SYNTAX (Replaces *ngIf, *ngFor, *ngSwitch)
================================================================================

  WHAT CHANGED:
  -------------
  Angular 17 introduces new BUILT-IN control flow syntax.
  Old *ngIf, *ngFor, *ngSwitch still work (deprecated, not removed).
  No immediate errors - but migration recommended for better performance.

  1. @if REPLACES *ngIf:
  ----------------------
  OLD (still works but deprecated):
    <div *ngIf="isVisible">Content</div>
    <div *ngIf="user; else noUser">Hello {{ user.name }}</div>
    <ng-template #noUser>No user found</ng-template>

  NEW (@if):
    @if (isVisible) {
      <div>Content</div>
    }

    @if (user) {
      <div>Hello {{ user.name }}</div>
    } @else {
      <div>No user found</div>
    }

    @if (status === 'active') {
      <div>Active</div>
    } @else if (status === 'pending') {
      <div>Pending</div>
    } @else {
      <div>Inactive</div>
    }

  2. @for REPLACES *ngFor:
  ------------------------
  OLD (still works but deprecated):
    <div *ngFor="let item of items; let i = index; trackBy: trackFn">
      {{ i }} - {{ item.name }}
    </div>

  NEW (@for) - NOTE: 'track' is REQUIRED in @for!:
    @for (item of items; track item.id) {
      <div>{{ item.name }}</div>
    } @empty {
      <div>No items found</div>
    }

    @for (item of items; track item.id; let i = $index) {
      <div>{{ i }} - {{ item.name }}</div>
    }

  IMPORTANT: @for REQUIRES track expression - cannot skip it!
  OLD *ngFor track was optional. NEW @for track is MANDATORY.

  AVAILABLE LOOP VARIABLES in @for:
    $index   - current index
    $first   - true if first item
    $last    - true if last item
    $even    - true if index is even
    $odd     - true if index is odd
    $count   - total count of items

  3. @switch REPLACES *ngSwitch:
  --------------------------------
  OLD (still works but deprecated):
    <div [ngSwitch]="status">
      <span *ngSwitchCase="'active'">Active</span>
      <span *ngSwitchCase="'pending'">Pending</span>
      <span *ngSwitchDefault>Unknown</span>
    </div>

  NEW (@switch):
    @switch (status) {
      @case ('active') {
        <span>Active</span>
      }
      @case ('pending') {
        <span>Pending</span>
      }
      @default {
        <span>Unknown</span>
      }
    }

  4. @defer - NEW DEFERRABLE VIEWS:
  ------------------------------------
  NEW in Angular 17 - lazy load sections of the template:
    @defer (on viewport) {
      <heavy-component />
    } @loading {
      <div>Loading...</div>
    } @error {
      <div>Failed to load</div>
    } @placeholder {
      <div>Placeholder content</div>
    }

  AUTO-MIGRATION COMMAND:
  ------------------------
  Angular CLI provides automatic migration:
  npx ng generate @angular/core:control-flow

  This automatically converts all *ngIf, *ngFor, *ngSwitch
  in your templates to the new @if, @for, @switch syntax.

  FILES AFFECTED (if migrating - ALL HTML templates):
  ---------------------------------------------------
  Every .html file that uses *ngIf, *ngFor, *ngSwitch
  (Potentially 200+ files in a large project like VTS)

  NOTE: This migration is OPTIONAL in Angular 17.
        Old directives still work - no build errors.
        Only migrate when ready for the new syntax.

SECTION 6 : ANGULAR 17 NEW FEATURES (Signals - Now Stable!)
================================================================================

  SIGNALS API (STABLE in Angular 17):
  -------------------------------------
  Signals were Developer Preview in v16. Now STABLE in v17.
  OPTIONAL - existing RxJS/Observable pattern still works.

  signal() - Create a reactive value:
    import { signal } from '@angular/core'
    count = signal(0)
    this.count.set(1)
    this.count.update(v => v + 1)
    console.log(this.count())  // call it like a function to read

  computed() - Derived value:
    import { computed } from '@angular/core'
    doubled = computed(() => this.count() * 2)

  effect() - Side effects:
    import { effect } from '@angular/core'
    constructor() {
      effect(() => console.log('count changed:', this.count()))
    }

  Signal-based Inputs (NEW in v17):
    import { input } from '@angular/core'
    name = input<string>()           // optional input
    name = input.required<string>()  // required input

  Signal-based ViewChild (NEW in v17):
    import { viewChild } from '@angular/core'
    myEl = viewChild<ElementRef>('myRef')

  NOTE: These are additive features. No existing code breaks.

SECTION 10 : ANGULAR 17 - NEW APPLICATION BUILDER (Optional Migration)
================================================================================

  WHAT IS THE NEW BUILDER:
  -------------------------
  Angular 17 introduces "@angular-devkit/build-angular:application"
  as the new default builder (replaces the old "browser" builder).
  Uses ESBuild + Vite for much faster builds.

  OLD builder still works in v17 - NO breaking change.
  But for future versions (v18+), old builder is deprecated.

  HOW TO SWITCH (angular.json changes):
  ---------------------------------------

  1. In architect.build section:
     OLD:
       "builder": "@angular-devkit/build-angular:browser",
       "options": {
         "main": "src/main.ts",
         "polyfills": ["zone.js"],
         ...
       }

     NEW:
       "builder": "@angular-devkit/build-angular:application",
       "options": {
         "browser": "src/main.ts",       <-- 'main' renamed to 'browser'
         "polyfills": ["zone.js"],
         ...
       }

  2. In architect.serve section:
     Keep as-is (serve builder auto-detects the build builder)

  3. outputPath format changes with new builder:
     OLD output:  dist/vts/
     NEW output:  dist/vts/browser/  (new builder adds /browser subfolder)
     FIX: Add "outputPath": { "base": "dist/vts", "browser": "" }
          to keep flat output directory

  BENEFIT OF NEW BUILDER:
  -------------------------
  Build time: Up to 67% faster than old builder
  Bundle size: Slightly smaller due to ESBuild optimization

  RECOMMENDATION: Keep old builder for risk-free migration.
                  Switch to new builder in a separate step after migration.

  KEY TypeScript 5.2 CHANGES:
  ----------------------------

  1. 'using' declarations (new keyword for resource management):
     const resource = using getResource()

     May affect some module barrel files.

     If using 'override' on class methods, TypeScript 5.2
     is stricter about correct usage.
