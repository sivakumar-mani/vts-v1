SECTION 2 : CRITICAL BREAKING CHANGE - BROWSER BUILDER REMOVED!
================================================================================

  WHAT CHANGED:
  -------------
  Angular 19 COMPLETELY REMOVES the old "browser" builder.
  "@angular-devkit/build-angular:browser" is NO LONGER AVAILABLE in Angular 19.
  You MUST switch to "@angular-devkit/build-angular:application" (ESBuild/Vite).

  ERROR YOU WILL SEE (without this fix):
  ----------------------------------------
  Error: Builder "@angular-devkit/build-angular:browser" is not found.

  CHANGES MADE TO angular.json:
  ------------------------------
  1. Builder renamed:
     OLD: "builder": "@angular-devkit/build-angular:browser"
     NEW: "builder": "@angular-devkit/build-angular:application"

  2. "main" key renamed to "browser":
     OLD: "main": "src/main.ts"
     NEW: "browser": "src/main.ts"

  3. outputPath format updated (to keep flat dist/Vts output):
     OLD: "outputPath": "dist/Vts"
     NEW: "outputPath": { "base": "dist/Vts", "browser": "" }
     NOTE: Without "browser": "", new builder outputs to dist/Vts/browser/ subdirectory.
           The object format keeps output flat at dist/Vts/ as before.

  4. Removed unsupported options (NOT valid in application builder):
     REMOVED: "vendorChunk": true / false
     REMOVED: "buildOptimizer": true / false
     REMOVED: "namedChunks": true / false
     KEPT:    "extractLicenses", "sourceMap", "optimization" (still supported)

  FILES CHANGED:
  --------------
  - angular.json  (architect.build section)

SECTION 3 : STANDALONE: FALSE - REQUIRED EXPLICIT DECLARATION
================================================================================

  WHAT CHANGED:
  -------------
  Angular 19 requires all non-standalone components, directives, and pipes
  to EXPLICITLY declare "standalone: false" in their decorators.

  Previously (Angular 16–18):
    @Component({ selector: 'app-foo', ... })  ← 'standalone' could be omitted

  Angular 19 (required):
    @Component({
      standalone: false,          ← MUST be explicitly set
      selector: 'app-foo', ...
    })

  WHY: Angular is transitioning to standalone-by-default in a future major version.
       Angular 19 emits deprecation warnings for components without explicit standalone.
       Angular 20 will enforce this as a hard error.

  WHAT WAS DONE:
  --------------
  An automated scan was run across all .ts files in src/app/.
  "standalone: false" was added as the first property to ALL @Component,
  @Directive, and @Pipe decorators that did not already have standalone specified.

  STATISTICS:
  -----------
  Files scanned    : 476
  Files modified   : 370  (standalone: false added)
  Files skipped    : 106  (no @Component/@Directive/@Pipe - services, models, etc.)

  AUTO-MIGRATION COMMAND (alternative):
  ----------------------------------------
  npx ng generate @angular/core:explicit-standalone-flag
  (This is the official Angular schematics command that does the same thing)

SECTION 5 : ANGULAR 19 NEW FEATURES
================================================================================

  5a. LINKED SIGNALS (NEW - Stable):
  ------------------------------------
  New reactive primitive for dependent state:
    import { linkedSignal } from '@angular/core'

    const selectedOption = linkedSignal({
      source: this.options,
      computation: options => options[0]  // resets when options changes
    })

  5b. RESOURCE API (Developer Preview):
  ----------------------------------------
  Async data loading with signal integration:
    import { resource } from '@angular/core'

    userResource = resource({
      request: () => this.userId(),
      loader: ({ request: id }) => fetch(`/api/users/${id}`).then(r => r.json())
    })
    // Access: userResource.value(), userResource.isLoading(), userResource.error()

  5c. INCREMENTAL HYDRATION (New for SSR):
  ------------------------------------------
  For SSR projects only (not applicable to this SPA):
    @defer (hydrate on idle) {
      <heavy-component />
    }

  5d. HOT MODULE REPLACEMENT (HMR) - On by Default:
  ---------------------------------------------------
  Angular 19 enables HMR for CSS/styles by default during dev server.
  Styles update without full page reload.
  No code change needed - works automatically with application builder.

  5e. TIME ZONE SUPPORT FOR PIPE:
  ---------------------------------
  DatePipe and formatDate now accept timezone offset objects.
  No breaking change - additive feature.

  5f. SIGNAL INPUT / OUTPUT IMPROVEMENTS:
  ----------------------------------------
  All signal-based APIs from v17/18 remain fully available:
    input(), output(), model(), viewChild(), contentChild()

  NOTE: All these are additive features. No existing code breaks.

SECTION 6 : PRIMENG - UPGRADE RECOMMENDATION
================================================================================

  CURRENT VERSION: primeng ^17.18.0
  RECOMMENDED FOR ANGULAR 19: primeng ^19.x.x

  WHY NOT UPGRADED NOW:
  ----------------------
  PrimeNG 17 → 19 is a TWO major-version jump with significant breaking changes.
  PrimeNG 18 and 19 introduced new theming architecture and API changes.
  To minimize risk, PrimeNG is kept at ^17.18.0 for this migration.
  Use "--legacy-peer-deps" during npm install to resolve peer dependency conflicts.

  FUTURE UPGRADE (PrimeNG 17 → 19):
  -----------------------------------
  PRIMENG 18 CHANGES:
  - New design token-based theming system (Aura theme default)
  - p-chips API changes
  - Various component API cleanups

  PRIMENG 19 CHANGES:
  - Built around Angular 19 standalone APIs
  - Further theming improvements
  - p-table, p-toast, p-paginator APIs may have minor updates

  RECOMMENDATION: Upgrade PrimeNG in a SEPARATE step after Angular 19 is stable.

  IF YOU UPGRADE NOW (primeng 17 → 19):
  -----------------------------------------
  1. Update package.json:  primeng: "^17.18.0" --> "^19.x.x"
  2. Check all module .ts files for import path changes
  3. Update theme import in styles.css
  4. Test all forms with p-table, p-toast, p-calendar (p-datepicker), p-select

SECTION 8 : TYPESCRIPT 5.6 CHANGES
================================================================================

  KEY TypeScript 5.6 CHANGES:
  ----------------------------

  1. --noUncheckedSideEffectImports (new strict flag):
     Enables errors for imports used only for side effects.
     NOT enabled in this project (strictTemplates: false) - no impact.

  2. Improved type narrowing:
     TypeScript 5.6 narrows types more precisely in certain patterns.
     May cause a few new type errors in files that relied on broader types.
     FIX: Add explicit type annotations where needed.

  3. Iterator helper methods (Iterator.from, etc.):
     New built-in iterator methods. Additive only.

  4. 'override' keyword checking improved.
     If using 'override' on class methods, TypeScript 5.6
     is stricter about correct usage.

  KEEP IN tsconfig.json (still required):
  ----------------------------------------
  "experimentalDecorators": true
  "useDefineForClassFields": false
  "skipLibCheck": true
  "strictTemplates": false  (already set in angularCompilerOptions)

SECTION 9 : APPLICATION BUILDER DIFFERENCES
================================================================================

  Old browser builder        Application builder (Angular 19)
  --------------------------  --------------------------------
  Webpack bundler             ESBuild + Vite bundler
  "main": "src/main.ts"       "browser": "src/main.ts"
  vendorChunk supported       vendorChunk NOT supported (auto)
  namedChunks supported       namedChunks NOT supported
  buildOptimizer supported    buildOptimizer NOT supported (always on)
  outputPath: string          outputPath: string or { base, browser }
  outputPath: dist/Vts        outputPath: { base: dist/Vts, browser: "" }

  PERFORMANCE IMPROVEMENT:
  -------------------------
  Build time: ~40-70% faster than old webpack builder
  Dev server: Near-instant HMR for styles and components
  Bundle: Slightly smaller due to ESBuild tree shaking

  BUNDLE OUTPUT:
  ---------------
  The angular.json uses:
    "outputPath": { "base": "dist/Vts", "browser": "" }
  This keeps output flat in dist/Vts/ (same as before).
  Without "browser": "", output would go to dist/Vts/browser/.

  SERVICE WORKER NOTE:
  --------------------
  If adding service workers in the future, the application builder
  supports @angular/service-worker natively (no extra config needed).
