SECTION 2 : CONFIG FILE CHANGES
================================================================================

  FILE: tsconfig.json
  -------------------
  CHANGE 1: target update
    "target": "ES2017"  -->  "target": "ES2022"
    REASON: Angular 15 defaults to ES2022 output for modern browsers

  CHANGE 2: useDefineForClassFields (add if not present)
    ADD: "useDefineForClassFields": false
    REASON: Prevents TypeScript 4.8 from using defineProperty semantics
            that break Angular decorators with ES2022 target

  CHANGE 3: lib update (if present)
    "lib": ["ES2017", "dom"]  -->  "lib": ["ES2022", "dom"]

  FILE: angular.json
  ------------------
  CHANGE 1: namedChunks (new default in v15)
    In build options, add if missing:
    "namedChunks": false  (for production)
    "namedChunks": true   (for development)

  CHANGE 2: budgets (component style limit)
    Angular 15 enforces stricter budgets for component styles
    Check: "maximumError": "6kb" for componentStyles budget

  NOTE: browserTarget is still used in Angular 15
        (browserTarget → buildTarget rename only happens in Angular 18)

SECTION 3 : ANGULAR MATERIAL 15 - MDC MIGRATION (BIGGEST CHANGE!)
================================================================================

  WHAT CHANGED:
  -------------
  Angular Material 15 internally migrated ALL components to MDC
  (Material Design Components for Web - Google's official MDC library).

  This changes:
    - Inner HTML structure of Material components
    - CSS class names used internally
    - Density/sizing system
    - Ripple behavior

  TWO OPTIONS AVAILABLE:
  ----------------------
  OPTION A: Use Legacy APIs (Quick Fix - Deprecated)
    - Import MatLegacy* modules instead of Mat* modules
    - Everything looks/works same as Angular 14
    - BUT: These will be removed in Angular 17!
    - RECOMMENDED only for quick migration

  OPTION B: Migrate to MDC Components (Permanent Fix)
    - Use the new MDC-based components
    - CSS customizations may break (inner HTML structure changed)
    - Use ng update schematics to auto-migrate

SECTION 4 : TYPED REACTIVE FORMS (Important for .ts files)
================================================================================

  WHAT CHANGED:
  -------------
  Angular 14 introduced Typed Reactive Forms as the DEFAULT.
  Any FormControl/FormGroup/FormArray now requires type parameters.

  IF MIGRATING FROM Angular 13 → 14 → 15:
  - If proper `ng update` was run in v14, forms are already updated to
    UntypedFormControl / UntypedFormGroup / UntypedFormArray
  - If not updated, v15 will show TypeScript errors

  CHANGES NEEDED IN TypeScript files:
  ------------------------------------
  IF getting type errors, replace with Untyped versions:

  OLD (Angular 13 style)           NEW (Angular 15 compatible)
  ----------------------------     ----------------------------
  FormControl                  --> UntypedFormControl
  FormGroup                    --> UntypedFormGroup
  FormArray                    --> UntypedFormArray
  FormBuilder                  --> UntypedFormBuilder

  IMPORT CHANGE:
  FROM: import { FormControl, FormGroup, FormBuilder } from '@angular/forms'
  TO:   import { UntypedFormControl, UntypedFormGroup,
                  UntypedFormBuilder } from '@angular/forms'

  FILES AFFECTED: ALL TypeScript component files that use Reactive Forms
  -----------------------------------------------------------------------
  Typically affects:
  - All files in src/app/master/**/*.component.ts
  - All files in src/app/screening/**/*.component.ts
  - All files in src/app/client-entry/**/*.component.ts
  - All files in src/app/verification/**/*.component.ts
  - All files in src/app/case/**/*.component.ts
  - All files in src/app/quality-check/**/*.component.ts
  - All service files that construct forms

  NOTE: VTS project already uses UntypedFormControl (seen in verification-details.component.ts)
        so this may already be handled.

SECTION 6 : ROUTER CHANGES (Angular 15 New Features)
================================================================================

  WHAT CHANGED:
  -------------
  Angular 15 introduced functional router guards (replaces class-based guards).
  Class-based guards still work but new functional style is recommended.

  OLD STYLE (Angular 14 - Class-based guard):
  -------------------------------------------
  @Injectable({ providedIn: 'root' })
  export class AuthGuard implements CanActivate {
    canActivate(route, state): boolean { ... }
  }

  NEW STYLE (Angular 15 - Functional guard):
  ------------------------------------------
  export const authGuard: CanActivateFn = (route, state) => {
    const authService = inject(AuthService);
    return authService.isLoggedIn();
  }

  FILES AFFECTED:
  ---------------
  - src/app/auth/can-activate.guard.ts  (or similar guard file)
  - src/app/app-routing.module.ts

  NOTE: Class-based guards still work in Angular 15.
        Migration to functional guards is OPTIONAL in v15.

  ROUTER OUTLET CHANGES:
  ----------------------
  No HTML changes needed for existing <router-outlet> tags.

SECTION 7 : ANGULAR 15 NEW APIs (Optional - Not Breaking)
================================================================================

  1. NgOptimizedImage Directive (New):
     ----------------------------------
     NEW directive from @angular/common for optimized image loading.
     OPTIONAL - doesn't break existing <img> tags.

     OLD:  <img src="logo.png" width="200" height="100">
     NEW:  <img ngSrc="logo.png" width="200" height="100">
     (Need to import NgOptimizedImage from @angular/common in module)

  2. Standalone Components (Became Stable in v15):
     -----------------------------------------------
     Can now create components without NgModule.
     @Component({ standalone: true, imports: [...] })
     OPTIONAL - existing NgModule pattern still fully supported.

  3. inject() Function (Enhanced):
     --------------------------------
     Can now use inject() in component constructors and functions.
     OPTIONAL - constructor injection still works.

  4. provideRouter() / provideHttpClient():
     -----------------------------------------
     New functional providers for standalone apps.
     OPTIONAL for NgModule-based apps.

  5. Title Strategy:
     -----------------
     Router can automatically set page <title> from route data.
     Add 'title' property to route definitions.
     OPTIONAL feature.

SECTION 10 : TYPESCRIPT 4.8 BREAKING CHANGES
================================================================================

  TYPE INFERENCE IMPROVEMENTS:
  -----------------------------
  TypeScript 4.8 has improved type narrowing which may cause NEW errors
  in code that previously compiled without issues.

  COMMON ISSUES:
  --------------
  1. Infer improvements - some previously valid type casts may fail
     FIX: Add explicit type annotation or use 'as' cast

  2. --strictFunctionTypes - function parameter types more strict
     FIX: Update callback signatures to match expected types

  3. Improved binding patterns narrowing
     FIX: Explicit type for destructured parameters

  FILES THAT COMMONLY NEED CHANGES:
  ----------------------------------
  - Service files with HTTP response handling
  - Files using complex generics
  - Files with Observable pipe operators and type inference

SECTION 11 : COMMON ERRORS AND FIXES
================================================================================

  ERROR 1: "Can't resolve '@angular/flex-layout'"
  -------------------------------------------------
  CAUSE : @angular/flex-layout removed from dependencies
  FIX   : npm install @ngbracket/ngx-layout@^15.0.0
          Update all module imports to @ngbracket/ngx-layout

  ERROR 2: "Module not found: MatLegacyButtonModule"
  ---------------------------------------------------
  CAUSE : Angular Material 15 moved legacy components to new paths
  FIX   : Change import from '@angular/material/button'
          to '@angular/material/legacy-button'
          (or use MDC version directly)

  ERROR 3: "Property 'value' does not exist on type 'AbstractControl'"
  --------------------------------------------------------------------
  CAUSE : Typed Forms - TypeScript now strictly checks form control types
  FIX   : Change FormControl → UntypedFormControl
          Change FormGroup → UntypedFormGroup
          Change FormBuilder → UntypedFormBuilder

  ERROR 4: "zone.js version mismatch"
  ------------------------------------
  CAUSE : Old zone.js ~0.11.x not compatible with Angular 15
  FIX   : Update zone.js to ~0.12.x in package.json

  ERROR 5: "CanActivate interface no longer exists"
  --------------------------------------------------
  CAUSE : Angular 15 moved guard interfaces to separate location
  FIX   : Change from implements CanActivate
          to implements CanActivateFn
          OR use functional guard approach

  ERROR 6: Mat component CSS broken (outline, borders, colors wrong)
  -------------------------------------------------------------------
  CAUSE : MDC migration changed inner HTML structure
  FIX   : Either use MatLegacy* modules
          OR update custom CSS overrides to MDC class names

SECTION 12 : MIGRATION STEPS (Step-by-Step)
================================================================================

  STEP 1: Backup current project
  --------------------------------
  git checkout -b feature/angular-15-upgrade

  STEP 2: Update package.json versions
  --------------------------------------
  Update all @angular/* packages to ^15.0.0
  Update zone.js to ~0.12.x
  Replace @angular/flex-layout with @ngbracket/ngx-layout@^15.0.0
  Update Kendo packages to ^11.0.0
  Update PrimeNG to ^15.0.0
  Update TypeScript to ~4.8.x

  STEP 3: Run npm install
  ------------------------
  npm install --legacy-peer-deps

  STEP 4: Run Angular migration schematics
  -----------------------------------------
  npx ng update @angular/core@15 @angular/cli@15
  npx ng update @angular/material@15

  NOTE: ng update @angular/material automatically offers to migrate
        components to either MDC or Legacy APIs.
        Select "Use Legacy APIs" for fastest migration path.

  STEP 5: Update flex-layout imports
  ------------------------------------
  Find all files:   grep -r "@angular/flex-layout" src/
  Replace with:     @ngbracket/ngx-layout

  STEP 6: Fix TypeScript errors
  ------------------------------
  npm run build
  Fix each TypeScript error shown

  STEP 7: Fix Template errors
  ----------------------------
  Check all HTML templates for breaking changes
  Fix Material MDC-related template issues

  STEP 8: Test build
  -------------------
  npm run build:prod
