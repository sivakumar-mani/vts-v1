SECTION 3 : CRITICAL BREAKING CHANGE - entryComponents REMOVED!
================================================================================

  WHAT CHANGED:
  -------------
  `entryComponents` in @NgModule decorator was deprecated since Angular 9 (Ivy).
  Angular 16 COMPLETELY REMOVES it - it is now a build error!

  ERROR YOU WILL SEE:
  -------------------
  error TS2353: Object literal may only specify known properties,
  and 'entryComponents' does not exist in type 'NgModule'

  FILES AFFECTED:
  ---------------
  ALL .module.ts files that have entryComponents array.

  CHANGE NEEDED:
  --------------
  REMOVE the entryComponents array entirely from @NgModule decorator.

  OLD (Angular 15 and below):
  ---------------------------
  @NgModule({
    declarations: [...],
    imports: [...],
    providers: [...],
    entryComponents: [
      CommonDialogComponent,
      CommonAlertsComponent,
      ConfirmDialogComponent,
      ...
    ],
    bootstrap: [AppComponent]
  })
  export class AppModule {}

  NEW (Angular 16):
  -----------------
  @NgModule({
    declarations: [...],
    imports: [...],
    providers: [...],
    bootstrap: [AppComponent]
  })
  export class AppModule {}

  NOTE: Components listed in entryComponents were used for dynamic component
        loading. In Ivy (Angular 9+), this is automatic - no need to list them.
        Simply delete the entryComponents array. No other code change needed.

  TYPICAL FILES TO CHECK AND FIX:
  ---------------------------------
  - src/app/app.module.ts                              (most likely has it)
  - src/app/master/master.module.ts
  - src/app/screening/screening.module.ts
  - src/app/client-entry/client-entry.module.ts
  - src/app/verification/verification.module.ts
  - src/app/case/case.module.ts
  - src/app/quality-check/quality-check.module.ts
  - src/app/reports/reports.module.ts
  - src/app/invoice/invoice.module.ts
  - src/app/common-methods/common-methods.module.ts
  + any other feature module with entryComponents

SECTION 4 : BREAKING CHANGE - ComponentFactoryResolver REMOVED
================================================================================

  WHAT CHANGED:
  -------------
  `ComponentFactoryResolver` was deprecated in Angular 13.
  Angular 16 completely removes it - error if used.

  ERROR YOU WILL SEE:
  -------------------
  error TS2305: Module '@angular/core' has no exported member 'ComponentFactoryResolver'

  OLD CODE (Angular 15):
  ----------------------
  import { ComponentFactoryResolver } from '@angular/core'

  constructor(private resolver: ComponentFactoryResolver,
              private vcr: ViewContainerRef) {}

  // Create component dynamically:
  const factory = this.resolver.resolveComponentFactory(MyComponent)
  const ref = this.vcr.createComponent(factory)

  NEW CODE (Angular 16):
  ----------------------
  import { ViewContainerRef } from '@angular/core'

  constructor(private vcr: ViewContainerRef) {}

  // Create component dynamically (direct - no factory needed):
  const ref = this.vcr.createComponent(MyComponent)

  FILES AFFECTED:
  ---------------
  Any TypeScript file that imports or uses ComponentFactoryResolver.
  Search command: grep -r "ComponentFactoryResolver" src/

  COMMON LOCATIONS:
  -----------------
  - src/app/common-methods/services/*.service.ts
  - src/app/common-methods/components/**/*.component.ts
  - Any component that opens dialogs or creates dynamic components

SECTION 5 : ROUTE GUARD CHANGES - CanLoad Deprecated
================================================================================

  WHAT CHANGED:
  -------------
  `CanLoad` interface (lazy route guard) is DEPRECATED in Angular 16.
  Replaced by `CanMatch`.

  CanLoad vs CanMatch:
  --------------------
  - CanLoad  : Prevents lazy module from loading at all
  - CanMatch : More powerful - can check route params/data too

  OLD (Angular 15 - CanLoad guard):
  ----------------------------------
  import { CanLoad } from '@angular/router'

  @Injectable({ providedIn: 'root' })
  export class AuthGuard implements CanLoad {
    canLoad(route: Route, segments: UrlSegment[]): boolean {
      return this.authService.isLoggedIn()
    }
  }

  In routing module:
  { path: 'master', canLoad: [AuthGuard], loadChildren: ... }

  NEW (Angular 16 - CanMatch):
  -----------------------------
  import { CanMatchFn } from '@angular/router'

  export const authGuard: CanMatchFn = (route, segments) => {
    const authService = inject(AuthService)
    return authService.isLoggedIn()
  }

  In routing module:
  { path: 'master', canMatch: [authGuard], loadChildren: ... }

  NOTE: CanActivate still works normally (no change needed).
        Only CanLoad is deprecated. CanActivate → no change.

  FILES AFFECTED:
  ---------------
  - src/app/auth/can-activate.guard.ts  (check if it uses CanLoad)
  - src/app/app-routing.module.ts       (canLoad → canMatch if used)

SECTION 6 : ANGULAR MATERIAL 16 CHANGES
================================================================================

  LEGACY MODULES STATUS IN v16:
  ------------------------------
  GOOD NEWS: MatLegacy* modules still available in Angular 16!
  (They are fully removed only in Angular 17)
  So if you migrated to Legacy in v15, no immediate change needed.

  MDC COMPONENTS (Default in v16):
  ----------------------------------
  If already using MDC components (not Legacy), no breaking changes.

  NEW MATERIAL TOKENS/THEMING SYSTEM:
  ------------------------------------
  Angular Material 16 introduces a new CSS custom properties (tokens) system.
  If you use custom theming via SCSS mixins, some mixin names changed.

  OLD THEMING (Angular 15):
  --------------------------
  @use '@angular/material' as mat;
  @include mat.core();
  $theme: mat.define-light-theme((...));
  @include mat.all-component-themes($theme);

  NEW THEMING (Angular 16 - recommended):
  ----------------------------------------
  @use '@angular/material' as mat;
  @include mat.core();
  $theme: mat.define-theme((
    color: (theme-type: light, primary: mat.$indigo-palette),
    typography: (font-family: 'Calibri'),
  ));
  html { @include mat.all-component-themes($theme); }

  NOTE: Old theming still works in v16 (no immediate break).
        New theming system is optional until v17+.

  MATERIAL DIALOG CHANGES:
  -------------------------
  MatDialog.open() return type is now stricter with generics.
  Some TypeScript errors may appear for dialog result types.

  FIX: Add explicit type to dialog open:
  OLD: this.dialog.open(MyDialogComponent, config)
  NEW: this.dialog.open<MyDialogComponent, DataType, ResultType>(MyDialogComponent, config)

SECTION 7 : ANGULAR 16 NEW FEATURES (Optional - Not Breaking)
================================================================================

  1. SIGNALS API (Developer Preview):
     -----------------------------------
     New reactive primitive for state management.
     OPTIONAL - Existing RxJS/Observable pattern still works perfectly.

     Example (new way):
       import { signal, computed, effect } from '@angular/core'
       count = signal(0)
       doubled = computed(() => this.count() * 2)
       effect(() => console.log(this.count()))

     NOTE: Do NOT use in production yet - Developer Preview in v16.
           Becomes stable in Angular 17.

  2. REQUIRED INPUTS (New Feature):
     ----------------------------------
     @Input can now be marked as required.
     No change needed for existing code.

     Example (new way):
       @Input({ required: true }) title!: string

  3. INPUT TRANSFORMS (New Feature):
     ------------------------------------
     @Input can now auto-transform values.

     Example (new way):
       @Input({ transform: booleanAttribute }) disabled = false
       @Input({ transform: numberAttribute }) count = 0

  4. DESTROYREF (New Service):
     ----------------------------
     Replaces ngOnDestroy for cleanup.
     OPTIONAL - ngOnDestroy still works.

     OLD WAY (still works):
       private destroy$ = new Subject<void>()
       ngOnDestroy() { this.destroy$.next(); this.destroy$.complete() }
       data$.pipe(takeUntil(this.destroy$)).subscribe(...)

     NEW WAY (optional):
       constructor(private destroyRef: DestroyRef) {}
       data$.pipe(takeUntilDestroyed(this.destroyRef)).subscribe(...)

  5. ROUTER: BIND TO COMPONENT INPUTS (New Feature):
     --------------------------------------------------
     Route params/data can now be automatically bound to component @Inputs.
     OPTIONAL - explicit ActivatedRoute injection still works.

     Enable in app.module.ts:
       RouterModule.forRoot(routes, { bindToComponentInputs: true })

     Then in component:
       @Input() id!: string  // auto-bound from route param :id

  6. AFTER RENDER HOOKS (New):
     ----------------------------
     afterRender() and afterNextRender() - new lifecycle hooks.
     OPTIONAL - use for DOM measurement after render.

  7. SSR IMPROVEMENTS:
     -------------------
     @angular/ssr package introduced.
     Better hydration support.
     OPTIONAL unless using SSR.

SECTION 8 : TYPESCRIPT 5.0 CHANGES (if upgrading TS)
================================================================================

  TYPESCRIPT 4.9 vs 5.0:
  ----------------------
  Angular 16 supports both TypeScript 4.9.x and 5.x.
  TypeScript 5.0 is recommended for new features.

  KEY TypeScript 5.0 CHANGES:
  ----------------------------

  1. Decorators (Native TC39 Decorators):
     TypeScript 5.0 uses the new TC39 decorator proposal by default.
     Angular still requires legacy decorators.

     KEEP in tsconfig.json:
       "experimentalDecorators": true
       "useDefineForClassFields": false
     (These override the TS5 defaults for Angular compatibility)

  2. 'const' type parameters:
     function identity<const T>(x: T): T { ... }
     No impact on existing code.

  3. All enums are union enums:
     More strict enum type checking.
     May cause errors if enums are used with string/number comparisons.

  4. --verbatimModuleSyntax:
     New flag - do not enable (not compatible with Angular).

  COMMON TypeScript 5.0 ERRORS IN ANGULAR:
  ------------------------------------------
  ERROR 1: "Argument of type 'x' is not assignable to parameter of type 'y'"
  FIX    : Add explicit type annotation

  ERROR 2: "Property does not exist on type 'never'"
  FIX    : Check conditional type narrowing logic

  ERROR 3: Decorator-related type errors
  FIX    : Ensure experimentalDecorators: true in tsconfig

SECTION 11 : HTTP CLIENT CHANGES
================================================================================

  WHAT CHANGED:
  -------------
  Angular 16 introduces new functional HTTP providers.
  OLD HttpClientModule still works but new approach is recommended.

  OLD WAY (Angular 15 - still works in v16):
  -------------------------------------------
  // app.module.ts
  import { HttpClientModule } from '@angular/common/http'
  @NgModule({
    imports: [ HttpClientModule, ... ]
  })

  NEW WAY (Angular 16 - optional):
  ----------------------------------
  // app.module.ts
  import { provideHttpClient } from '@angular/common/http'
  @NgModule({
    providers: [ provideHttpClient() ]
  })

  NO ACTION REQUIRED: HttpClientModule still works in Angular 16.
  Only switch if doing a major refactor.

  HTTP INTERCEPTORS (if using new functional style):
  ---------------------------------------------------
  OLD (class-based - still works):
    @Injectable()
    export class MyInterceptor implements HttpInterceptor { ... }

  NEW (functional - optional):
    export const myInterceptor: HttpInterceptorFn = (req, next) => { ... }

  FILES AFFECTED:
  ---------------
  - src/app/interceptor.ts  (optional - no need to change if working)
  - src/app/app.module.ts   (optional - HttpClientModule stays)
